## 프롬프트
이 프로젝트를 지침 7번 보안 기준으로 점검해줘. 발견한 것을 먼저 알려주고, 고치는 건 내가 고른 뒤에 해줘.
- 쓰는 서비스: {쓰는 서비스}
- 저장하는 개인정보: {저장하는 개인정보}

## 빈칸
- 쓰는 서비스: 예) Supabase, 토스페이먼츠, Claude API
- 저장하는 개인정보: 예) 이메일, 전화번호, 예약 기록

## 왜 이렇게 썼나
- 비밀 키, RLS, 서버 검증 같은 점검 항목은 적지 않았습니다. 지침 7번에 있습니다.
- "먼저 알려주고 고치는 건 나중에"를 넣었습니다. 보안 수정은 범위가 넓어지기 쉬워서, 무엇을 고칠지 사용자가 고르게 했습니다.

## 기대 응답
- 코드와 설정을 열어본 뒤 7번 항목별로 결과를 알려줍니다.
- 키가 코드나 git 기록에 있으면 지우는 것으로는 부족하고 재발급해야 한다고 알려줍니다.
- 비밀 값을 대화에 그대로 보여주지 않습니다.
- 확인하지 못한 것(실제 DB 정책 등)은 확인하지 못했다고 말합니다.

## 실패 신호
- 발견한 키 값을 답변에 그대로 적습니다.
- 묻지 않고 여러 파일을 한꺼번에 고칩니다.
- 열어보지 않고 "문제 없습니다"라고 합니다.

## 이어서 쓰는 문장
- 다른 사용자 계정으로 남의 데이터에 접근이 막히는지 테스트하는 방법을 알려줘.
