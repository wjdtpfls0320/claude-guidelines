## 프롬프트
지금 프로젝트에 기능을 추가하고 싶어.
- 추가할 기능: {추가할 기능}
- 필요한 이유: {필요한 이유}
- 건드리면 안 되는 것: {건드리면 안 되는 것}

## 빈칸
- 추가할 기능: 예) 예약 취소 대기 신청
- 필요한 이유: 예) 마감된 수업에 빈자리가 나도 회원이 알 방법이 없음
- 건드리면 안 되는 것: 예) 결제 관련 코드, 없으면 "없음"

## 왜 이렇게 썼나
- "기존 코드를 먼저 읽어봐"는 뺐습니다. 지침 1번이 열어보지 않은 코드를 추측하지 않게 합니다.
- 필요한 이유를 넣었습니다. 이유를 알면 AI가 기획서에서 더 작은 해결 방법을 제안할 수 있습니다.
- 건드리면 안 되는 범위는 AI가 알 수 없는 정보라 직접 적게 했습니다.

## 기대 응답
- 관련 코드를 실제로 열어본 뒤 답합니다.
- 새 화면이나 데이터 구조가 생기면 기획서를 먼저 쓰고 승인을 기다립니다.
- 기획서에 없던 라이브러리가 필요하면 추가하기 전에 이름과 이유를 알리고 승인받습니다.

## 실패 신호
- 코드를 읽지 않고 구조를 짐작해서 답합니다.
- 기획서 없이 바로 구현합니다.
- 요청과 관계없는 기존 코드를 같이 고칩니다.

## 이어서 쓰는 문장
- 이 기능 없이도 같은 문제를 푸는 더 작은 방법이 있으면 알려줘.
