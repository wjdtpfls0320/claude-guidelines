## 프롬프트
코드를 점검해줘. 고치지는 말고 목록으로만 알려줘.
- 볼 범위: {볼 범위}
- 특히 걱정되는 점: {걱정되는 점}

## 빈칸
- 볼 범위: 예) 예약 기능 전체 (src/reservation 폴더)
- 걱정되는 점: 예) 동시에 예약이 몰릴 때. 없으면 "없음"

## 왜 이렇게 썼나
- "읽지 않은 파일은 추측하지 마"는 뺐습니다. 지침 1번이 맡습니다.
- "고치지는 말고"는 남겼습니다. 지침 3번은 요청과 관계없는 문제를 알리기만 하게 하지만, 점검 요청은 "고쳐달라"로 읽힐 수 있어서 분명히 적었습니다.

## 기대 응답
- 파일을 실제로 열어본 뒤, 어느 파일의 어느 부분인지와 함께 문제를 알려줍니다.
- 확실한 문제와 가능성만 있는 문제를 나눠서 알려줍니다.
- 보지 못한 파일이 있으면 보지 못했다고 말합니다.

## 실패 신호
- 점검하면서 코드를 고칩니다.
- 파일을 열지 않고 흔한 문제를 나열합니다.
- 문제가 없는데 억지로 만들어 냅니다.

## 이어서 쓰는 문장
- 이 중에 출시 전에 꼭 고쳐야 하는 것만 골라서, 하나씩 고쳐줘.
