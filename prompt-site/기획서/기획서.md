## 1. 목적과 한 줄 소개

**한 줄 소개:** 개인 설정에 [`지침.txt`](../../지침.txt)를 넣어둔 상태에서 AI 채팅에 그대로 붙여 넣어 쓰는 프롬프트를, 분야와 상황별로 골라 쓰는 사이트.

**목적**

- 지침이 이미 처리하는 것(정확성, 질문 기준, 기획서 먼저, 보안 등)은 프롬프트에서 빼서, 프롬프트는 짧게 쓰고 답변 품질은 지침으로 맞춥니다.
- 분야(개발, 글쓰기, 업무, 학습, 사업 기획 등)와 상황(새 기능 만들기, 버그 고치기, 보고서 쓰기 등)으로 나눠, 지금 필요한 프롬프트를 바로 찾게 합니다.
- **지침이 바뀌면 프롬프트도 따라 바뀌게** 합니다. 각 프롬프트가 지침의 어느 항목에 기대고 있는지 기록해두고, 그 항목이 바뀌면 해당 프롬프트를 찾아내 다시 검토합니다(9장).

| 누가 | Claude, ChatGPT 같은 AI 채팅을 업무나 개인 프로젝트에 자주 쓰는 한국어 사용자. 비개발자가 AI로 웹·앱을 만드는 경우 포함 |

| 전제 | 방문자 대부분은 이 지침을 아직 쓰지 않음. 그래서 사이트가 지침 전문도 공개하고 설정 방법을 안내하며, 프롬프트는 지침과 짝으로 쓰는 것을 전제로 씁니다 |

대상 AI: Claude 중심. ChatGPT·Gemini는 개인 설정 위치만 안내합니다.

## 4. 핵심 기능과 화면 흐름

### 핵심 기능 (첫 버전)

1. **분야 → 상황 → 프롬프트 탐색**: 분야를 고르면 상황별 프롬프트 목록이 나옵니다.
2. **검색**: 프롬프트 제목, 상황, 태그로 검색.
3. **빈칸 채우기 + 복사**: 프롬프트 안의 `{만들 프로그램}` 같은 빈칸을 입력칸으로 채우고, 완성된 프롬프트를 한 번에 복사. 입력값은 브라우저 안에서만 쓰고 서버로 보내거나 저장하지 않습니다.
4. **지침 배포**: 지침 전문 복사, Claude·ChatGPT 등에 넣는 방법 안내.
5. **지침 연동 표시**: 프롬프트마다 "이 프롬프트가 기대는 지침 항목"(예: 4번 기획서 먼저, 7번 보안)과 "몇 번째 지침 버전에서 검토했는지"를 보여줍니다.
6. **업데이트 기록**: 지침이 언제 어떻게 바뀌었고, 그에 따라 어떤 프롬프트가 바뀌었는지.

### 첫 버전에서 뺀 것

- 로그인, 즐겨찾기, 내 프롬프트 저장
- 사이트 안에서 AI가 맞춤 프롬프트를 생성하는 기능 (넣으면 서버, API 비용, AI 기본법 고지 의무가 생깁니다. 나중 단계로 미룸)
- 사용자 프롬프트 등록·댓글

### 화면 흐름

```
홈 ─┬─ 분야 선택 → 상황별 프롬프트 목록 → 프롬프트 상세(빈칸 채우기 → 복사)
    ├─ 검색 → 결과 목록 → 프롬프트 상세
    └─ 지침 시작하기 → 지침 복사 → (AI 서비스 개인 설정에 붙여 넣기) → 홈으로
프롬프트 상세 → "이 지침 항목 보기" → 지침 페이지의 해당 항목
```

## 5. 화면 목록

### 5-1. 홈

- 요소: 한 줄 소개, 분야 카드(아이콘 + 분야 이름 + 프롬프트 수), 검색창, "지침 먼저 설정하기" 안내 띠, 최근 업데이트 3건
- **가장 눈에 띄어야 할 것:** 분야 카드. 방문자가 3초 안에 자기 분야를 누를 수 있어야 합니다.

### 5-2. 분야 페이지 (예: 개발)

- 요소: 분야 설명 한 줄, 상황별로 묶인 프롬프트 목록(제목, 한 줄 설명, 기대는 지침 항목 배지)
- **가장 눈에 띄어야 할 것:** 상황 이름(예: "새 기능을 만들 때", "오류를 고칠 때"). 방문자는 분야보다 "지금 하려는 일"로 고르기 때문입니다.

### 5-3. 프롬프트 상세

- 요소
  - 제목, 언제 쓰는지 한 줄
  - 빈칸 입력칸(칸마다 이름표 label을 붙임. 예: "만들 것")과, 입력값이 반영된 프롬프트 미리보기
  - 복사 버튼
  - 이 프롬프트가 기대는 지침 항목(눌러서 해당 항목으로 이동)
  - 왜 이렇게 썼는지(지침이 처리하므로 뺀 것, 대신 넣은 것)
  - 기대 응답과 실패 신호: 이 프롬프트를 넣었을 때 AI가 해야 할 행동과, 잘못된 답변의 신호. 저장소의 [`테스트_시나리오.md`](../../테스트_시나리오.md) 형식을 따릅니다.
  - 지침 버전, 마지막 검토일
- **가장 눈에 띄어야 할 것:** 완성된 프롬프트와 복사 버튼.

예시 화면 문구 (**예시입니다.** 실제 프롬프트는 받으실 예시를 기준으로 다시 씁니다):

> **새 기능 기획부터 시작하기**
> 만들고 싶은 것만 설명하면, 지침 4번에 따라 AI가 기획서부터 씁니다.
>
> `{만들 것}을 만들고 싶어. 쓰는 사람은 {누가}이고, {어떤 상황}에서 써. 기획서부터 써줘.`
>
> 기대는 지침: 2. 질문 기준 · 4. 기획서 먼저 · 5. 디자인 표현
> 지침 v2026-11-05 기준 · 2026-11-12 검토

### 5-4. 검색 결과

- 요소: 검색어, 결과 수, 결과 목록(분야 표시 포함)
- **가장 눈에 띄어야 할 것:** 결과 제목과 상황 설명.

### 5-5. 지침 시작하기

- 요소: 지침이 무엇이고 왜 쓰는지 3줄, 지침 전문(항목별 접기/펼치기), 전체 복사 버튼, 설정 방법 안내(Claude 개인 설정은 자세히, ChatGPT·Gemini는 설정 위치만), 항목별 근거([`README.md`](../../README.md) 내용 공개) 링크
- **가장 눈에 띄어야 할 것:** 전체 복사 버튼과 "어디에 붙여 넣는지" 안내.

### 5-6. 업데이트 기록

- 요소: 날짜순 목록. 각 항목에 지침 변경 내용, 다시 검토한 프롬프트 목록
- **가장 눈에 띄어야 할 것:** 날짜와 바뀐 지침 항목.

### 5-7. 소개 / 정책 페이지

- 소개, 개인정보처리방침, 이용약관, 사업자 정보, 문의 방법
- 처리방침·약관·사업자 정보는 **초안 페이지**로 만들고, 모든 화면 하단(푸터)에서 갈 수 있게 연결합니다. 초안이라 전문가 확인이 필요하다고 표시합니다.
- 사업자 정보처럼 알려주시지 않은 값은 지어내지 않고 `[채울 자리: 상호]`처럼 비워둡니다.
- 소개 문구에 "국내 1위", "가장 정확한" 같은 근거 없는 주장이나 지어낸 이용 후기는 넣지 않습니다.

## 9. 지침 연동 구조 (지침이 바뀌면 프롬프트도 바뀌게)

이 사이트의 핵심 차별점이라 따로 적습니다.

### 원칙

- **지침의 원본은 하나**: 저장소 루트의 `지침.txt`. 사이트는 이 파일을 빌드할 때 읽습니다. 사이트용 사본을 따로 두지 않습니다.
- **프롬프트는 자기가 기대는 항목을 기록**: 각 프롬프트 파일 앞부분에 기대는 지침 항목 번호와, 검토할 때의 그 항목 내용 지문(해시)을 적습니다.

```yaml
# 프롬프트 파일 앞부분 예시
id: dev-new-feature
분야: 개발
상황: 새 기능을 만들 때
지침항목: [2, 4, 5]
지침지문: { "2": "a1b2c3", "4": "d4e5f6", "5": "0718ab" }
검토일: 2026-11-12
```

### 흐름

1. `지침.txt`를 고치고 커밋합니다.
2. 빌드할 때 동기화 점검 스크립트가 `지침.txt`를 항목별(`[적용 방법]`, `1. 정확성 [항상]` …)로 나누고 각 항목의 지문을 계산합니다.
3. 프롬프트에 적힌 지문과 지금 지문이 다르면 그 프롬프트를 **"검토 필요"** 로 표시하고 목록을 출력합니다.
4. 검토 필요 프롬프트는 공개 목록에서 빠집니다(기본값). 검토를 마치고 지문과 검토일을 갱신하면 다시 공개됩니다.
5. 업데이트 기록 페이지에 "지침 몇 번 항목 변경 → 다시 검토한 프롬프트" 가 남습니다.

### 선택 사항: AI로 수정 초안 만들기

- 검토 필요 프롬프트를 Claude API에 보내 새 지침 기준 수정 초안을 받는 스크립트를 둘 수 있습니다. **초안은 사람이 검토한 뒤에만 반영**합니다.
- 운영자 컴퓨터에서만 실행하고, API 키는 `.env`(git 제외)에 둡니다. 사이트 방문자는 이 기능과 관계없습니다.

## 11. 보안 설계

첫 버전은 서버, 데이터베이스, 로그인이 없는 정적 사이트라 공격 면이 작습니다. 그래도 아래는 지킵니다.

- **비밀 키**: 첫 버전에는 비밀 키가 없습니다. 나중에 수정 초안 스크립트(9장)를 넣으면 Claude API 키는 운영자 컴퓨터의 `.env`에만 두고, `.env`는 `.gitignore`에 넣고 `.env.example`에 변수 이름만 남기고, API 사용량 상한을 설정합니다.
- **누가 어떤 데이터에 접근하는지**: 저장하는 사용자 데이터가 없습니다. 빈칸 입력값은 브라우저 메모리에서만 쓰고 서버로 보내지 않습니다.
- **출력**: 빈칸 입력값은 `textContent`로만 화면에 넣고 `innerHTML`은 쓰지 않습니다.
- **AI 초안**: 선택 기능을 쓸 때 AI가 만든 초안은 믿을 수 없는 입력으로 보고, 사람이 검토한 뒤에만 반영합니다.
- **보안 헤더**: 호스팅 설정에서 CSP 등 기본 보안 헤더를 켭니다.
- 나중에 로그인·저장 기능을 넣으면 보안 설계를 다시 씁니다(인증 서비스, RLS 등).

**차별점: 어떤 고객이 어떤 상황에서 기존 것 대신 이걸 고르나**

- **AI로 앱을 만드는 비개발자가, 기획·보안·법 점검을 빠뜨릴까 걱정될 때.** 기존 모음은 프롬프트 한 개 단위라 매번 길게 조건을 붙여야 하지만, 여기서는 지침을 한 번 설정하면 짧은 프롬프트로도 기획서, 보안 점검, 출시 전 법 점검이 따라옵니다.
- **"이 프롬프트가 지금도 맞나?"가 궁금할 때.** 각 프롬프트에 기대는 지침 항목, 검토 버전, 기대 응답과 실패 신호가 붙어 있고, 지침이 바뀌면 다시 검토됩니다. 기존 모음은 대부분 한 번 올리고 끝입니다.
- **한국어·한국 법 기준이 필요할 때.** 해외 모음은 한국 개인정보보호법, AI 기본법 같은 내용을 다루지 않습니다.

**경쟁 서비스가 더 나은 점**

- 프롬프트 수와 분야 폭(PromptBase 수십만 개), 커뮤니티 참여, 이미지 생성 등 다양한 용도, ChatGPT 안에서 바로 쓰는 확장 프로그램(AIPRM).

**따라 하기 어려운 이유**

- 강한 것은 **없습니다.** 지침과 프롬프트는 공개되면 복사할 수 있습니다. 쌓아갈 수 있는 것은 지침 업데이트와 테스트 기록의 꾸준함, 그로 인한 신뢰 정도입니다. 운영자 본인의 경험이나 자원 같은 강점은 알려주시면 추가합니다('미정 질문' 11번).

## 14. 만드는 순서 (승인 후)

1. 프롬프트 예시를 받아 분야·상황 목록과 프롬프트 파일 형식 확정
2. 지침 파서와 동기화 점검 스크립트 (테스트 포함)
3. 화면: 홈 → 분야 → 상세(빈칸·복사) → 지침 → 검색 → 업데이트 기록
4. 첫 콘텐츠 20~30개 작성과 새 대화 테스트
5. 정책 문서 초안 페이지(푸터 연결), 출시 전 점검표 확인. 점검표 항목별로 반영한 것, 반영하지 못한 것, 정보를 주셔야 채울 수 있는 것을 정리해 보고
6. 배포

구현 중에 기획서에 없는 화면이 필요해지면(점검표를 맞추기 위한 화면 포함, 정책 문서 초안 페이지만 예외) 먼저 알리고 승인을 기다립니다. 그동안은 그 화면 없이 만들 수 있는 데까지만 만듭니다.
